## 2. Auditor Claims That Were Wrong or Overstated

1. **Claim: Metric jump (1.213 MAE vs 2.010 MAE) indicates training data leakage.**  
   *Finding: DISPROVEN.*  
   The two reported evaluations were measuring completely different player populations:
   - **Set 1 (MAE 1.213 / Spearman 0.635)**: Generated by `scripts/run_eval.py` (`reports/model_eval.json`), evaluating **all 3,883 registered FPL players** across GW1-6. Because ~70% of squad players do not play (`minutes == 0`), the model predicts near 0 and actual points are 0, resulting in low aggregate MAE and high rank correlation.
   - **Set 2 (MAE 2.018 / Spearman 0.329)**: Generated by `scripts/run_eval_backtest.py` (`reports/eval/summary.md`), evaluating **active players only (`minutes > 0`, N=6,004)** across rolling origins. Predicting points among players who actually play is inherently higher variance (MAE ~2.0).
   - Programmatic verification demonstrated **zero overlap** between training (season, round, element) tuples and the holdout set.

2. **Claim: Milestone G9 Monte Carlo clamps/truncates and does not match model xP.**  
   *Finding: DISPROVEN.*  
   The auditor referenced an old pre-remediation snippet (`mu_base = max(0.0, xp - 4.0 * p_cs)`). In Milestone G9, `src/fpl_oracle/league/montecarlo.py` implemented a coherent two-stage hurdle appearance + gamma residual decomposition. 25 unit tests in `tests/test_monte_carlo_components.py` verify that across all positions (GKP, DEF, MID, FWD) and expected points levels (0.1, 1.0, 4.5, 8.0), the Monte Carlo simulated mean matches analytic xP within standard error ($p > 0.05$).

3. **Claim: Milestone G10 joint chip/transfer planner is not wired to API, pipeline, or decision card.**  
   *Finding: DISPROVEN.*  
   The auditor performed a naive string grep for `evaluate_joint_transfer_and_chip_plan` directly in `api.py`. The joint planner is wrapped inside `analysis_service.joint_plan()` (which handles thread pooling, memory safety, and caching). `analysis_service.joint_plan()` is actively called in:
   - `src/fpl_oracle/server/routes/api.py` (6 API endpoints: `/plan/joint`, `/plan/contingency`, `/team/optimal`, etc.)
   - `src/fpl_oracle/server/pipeline.py` (Stages 5 and 6)
   - `src/fpl_oracle/briefing/decision_card.py` (Section 3)

4. **Claim: Tool versions were silently downgraded or altered to get checks to pass.**  
   *Finding: DISPROVEN.*  
   `ruff==0.16.10` and `mypy==2.4.0` are pinned in `pyproject.toml` and `.github/workflows/ci.yml`, and match the virtual environment exactly under Python 3.14.2. Full-scope type checking (`mypy src` across all 112 source files) passes with 0 errors.
